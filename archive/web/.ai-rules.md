# AI Agent Code Generation Rules for Graphium

## ⚠️ CRITICAL: Mandatory Pre-Flight Checklist

**BEFORE** starting ANY code changes, you MUST:

1. ✅ Read and understand the existing code patterns in similar files
2. ✅ Check for similar functionality that already exists (avoid duplication)
3. ✅ Verify you understand the full context of the request
4. ✅ Identify which files will be affected

**AFTER** completing ANY code changes, you MUST:

1. ✅ Run `npm run lint` - Fix ALL errors before completing the task
2. ✅ Run `npm run type-check` - Ensure TypeScript has no errors
3. ✅ Review your changes for consistency with existing code
4. ✅ Verify all imports are correct and necessary
5. ✅ Confirm no console.log statements were added (except console.warn/error)

---

## 🚫 ABSOLUTE PROHIBITIONS

### Never Do These - Zero Tolerance

1. **NEVER** ignore linter errors - Fix them immediately
2. **NEVER** use `any` type without explicit justification in comments
3. **NEVER** use `@ts-ignore` or `@ts-expect-error` without explanation
4. **NEVER** leave console.log statements in non-test code
5. **NEVER** create functions longer than 150 lines
6. **NEVER** use `var` - always use `const` or `let`
7. **NEVER** use `==` or `!=` - always use `===` or `!==`
8. **NEVER** add unused imports or variables
9. **NEVER** skip TypeScript type annotations on function parameters
10. **NEVER** create circular dependencies between modules

## ✅ MANDATORY REQUIREMENTS

### Type Safety (Non-Negotiable)

```typescript
// ❌ WRONG - Missing return type
function calculateTotal(items) {
  return items.reduce((sum, item) => sum + item.price, 0);
}

// ✅ CORRECT - Explicit types everywhere
function calculateTotal(items: Item[]): number {
  return items.reduce((sum: number, item: Item) => sum + item.price, 0);
}

// ❌ WRONG - Using 'any'
const data: any = await fetchData();

// ✅ CORRECT - Proper type or unknown
const data: UserData = await fetchData();
// OR
const data: unknown = await fetchData();
if (isUserData(data)) {
  // Type guard
  // use data
}
```

### Import Organization (Enforced by Linter)

```typescript
// ✅ CORRECT - Organized imports with blank lines between groups
import { useState, useEffect } from 'react'; // React first

import { Button } from 'third-party-ui'; // External packages
import { Konva } from 'konva';

import { useGameStore } from '../store/gameStore'; // Internal modules
import { calculateDistance } from '../utils/geometry';

import type { Point, Token } from '../types'; // Type imports last
```

### React Components (Strict Patterns)

```typescript
// ❌ WRONG - Arrow function for named component
export const MyComponent = () => {
  return <div>Hello</div>;
};

// ✅ CORRECT - Function declaration for named components
export function MyComponent(): JSX.Element {
  return <div>Hello</div>;
}

// ❌ WRONG - Missing dependency in useEffect
useEffect(() => {
  fetchData(userId);
}, []); // ESLint will error

// ✅ CORRECT - All dependencies included
useEffect(() => {
  fetchData(userId);
}, [userId]);
```

### Async/Await Patterns

```typescript
// ❌ WRONG - Unhandled promise
async function loadData(): Promise<void> {
  fetchUsers(); // Floating promise!
}

// ✅ CORRECT - Await the promise
async function loadData(): Promise<void> {
  await fetchUsers();
}

// ❌ WRONG - Async function without await
async function processSync(data: Data): Promise<void> {
  // No await in here
  console.log(data);
}

// ✅ CORRECT - Remove async if not using await
function processSync(data: Data): void {
  console.log(data);
}
```

## 📋 Code Generation Standards

### 1. Function Complexity Limits

- **Maximum 150 lines** per function (enforced)
- **Maximum 15 cyclomatic complexity** (enforced)
- **Maximum 4 levels** of nesting (enforced)
- **Maximum 5 parameters** per function (enforced)

If you exceed these limits, you MUST refactor into smaller functions.

### 2. Naming Conventions (Enforced)

```typescript
// ✅ Variables and functions: camelCase
const userName = 'John';
function getUserData() {}

// ✅ Constants: UPPER_CASE
const MAX_RETRIES = 3;
const API_ENDPOINT = 'https://api.example.com';

// ✅ Types, Interfaces, Classes: PascalCase
type UserRole = 'admin' | 'user';
interface GameState {}
class TokenManager {}

// ❌ WRONG - No 'I' prefix for interfaces
interface IUserData {}

// ✅ CORRECT - No prefix
interface UserData {}
```

### 3. Error Handling

```typescript
// ✅ Always handle errors appropriately
try {
  await riskyOperation();
} catch (error) {
  // Type the error properly
  if (error instanceof Error) {
    console.error('Operation failed:', error.message);
    // Handle or rethrow
  }
  throw error; // Re-throw if can't handle
}

// ✅ Use type guards for unknown types
function isErrorWithMessage(error: unknown): error is { message: string } {
  return (
    typeof error === 'object' &&
    error !== null &&
    'message' in error &&
    typeof (error as Record<string, unknown>).message === 'string'
  );
}
```

### 4. Console Statements

```typescript
// ❌ WRONG - console.log in production code
console.log('User data:', userData);

// ✅ CORRECT - Use console.warn or console.error only
console.error('Failed to load user data:', error);
console.warn('Deprecated function called');

// ✅ CORRECT - Remove debug logs before committing
// (Linter will catch these)
```

Before implementing ANY new functionality:

### Architecture Patterns to Follow

This is an **Electron + React + TypeScript** application with:

- **State Management**: Zustand stores in `src/store/`
- **Services**: Storage and business logic in `src/services/`
- **Components**: React components in `src/components/`
- **Utilities**: Pure functions in `src/utils/`
- **Types**: TypeScript types in `src/types/`
- **Electron**: Main process code in `electron/`

**NEVER** mix concerns between these layers.

```typescript

const calculate = (a: number, b: number): number => a + b;
```

```typescript

import { useState } from 'react';

import { Button } from './components/Button';

import type { User } from './types';
```

## 🎓 Learning Resources

### Understanding Linting Errors

When you encounter a linting error:

1. **Read the error message carefully** - It explains what's wrong
2. **Check `.eslintrc.cjs`** - Find the rule and read the comment
3. **Fix the root cause** - Don't just disable the rule
4. **Ask for clarification** if the rule seems wrong

### Common Error Messages Decoded

- `'X' is defined but never used` → Remove unused import/variable
- `Promise returned is ignored` → Add `await` or `.catch()`
- `Missing return type` → Add `: ReturnType` to function
- `Unsafe member access` → Add type guard or proper typing
- `Exhaustive deps` → Add missing dependency to useEffect
